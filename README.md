# TwinCAT Automation Research Playbook

## 1) 项目定位

本仓库用于系统化研究 TwinCAT 3 Automation Interface（重点版本：4026）在“从工程创建到激活”全流程中的自动化可替代能力，目标是：

- 把 UI 点击步骤尽可能替换为可复现的 C# 自动化代码。
- 对“未直接暴露为属性/接口”的能力，优先探索 `ITcSmTreeItem::ConsumeXml()` / `ProduceXml()` 的可行路径。
- 对必须落到 TMC 的改动，给出可追踪、可回滚、可激活验证的标准流程。

---

## 2) 当前研究主线（对应你的任务）

### 主线 A：安装并对齐 TwinCAT 4026 环境

**目标**
- 固化可复现实验环境（TwinCAT、VS、XAE、权限、运行态）。

**交付**
- 环境清单（版本、安装选项、补丁）。
- “最小可运行”验证记录（本工具可连接 DTE 并执行至少 1 个操作）。

---

### 主线 B：梳理 TwinCAT 页面可远程控制项与 ID/API

**目标**
- 枚举“界面上的按钮/菜单动作”与对应自动化调用方式。

**优先级顺序**
1. 直接 API（如 `ITcSysManager` / `ITcSmTreeItem` 公开方法）。
2. `ConsumeXml()` 命令式调用。
3. 最后才考虑文件层改动（TMC/XML 直接编辑）。

**交付**
- 控件/动作映射表（UI 动作 -> 自动化入口 -> 证据）。
- 每项动作至少一条“成功调用”证据（日志/截图/输出 XML）。

---

### 主线 C：深入探索 `ConsumeXml()` 能力边界

**目标**
- 不做泛泛总结，而是“可执行探索”：对每个目标动作，给出可尝试 XML 模板与结果。

**方法**
- 用 `ProduceXml()` 先导出当前节点 XML，观察可写字段与 `Methods` 结构。
- 设计最小改动 XML（一次只改一个字段/方法），逐步验证。
- 记录失败模式（报错、静默无效、版本差异）。

**重点产物**
- `ConsumeXml` 实验矩阵：`TreeItem` 路径、输入 XML、期望、实际、结论。
- 对“任务 2 中缺失 API”项，给出“任务 6 的每一步可用 XML 替代方案”。

---

### 主线 D：TMC 生成/发布/自动修改全链路

**目标**
- 回答三个问题：何时生成、发布到哪里、修改后如何激活生效。

**必须项**
- “UI 上的 TMC 操作”与“等价 TMC 文件操作”的对照说明。
- 修改后必须执行的步骤（如 code generator / publish / build / activate）及顺序。
- 明确建议：尽量优先使用主线 B/C，避免直接硬改 TMC。

**交付**
- TMC 生命周期图（生成 -> 发布 -> 实例引用 -> 激活）。
- TMC 变更 SOP（含备份、回滚、验证检查点）。

---

### 主线 E：专题问题

**需要给出实验结论**
- TMC 是否可改 `Data Area` / `Pointer`，改后在哪一步被覆盖或保留。
- `Parameters` 的 GUID 是否可自生成，哪些场景有效，哪些会被 TwinCAT 重写或拒绝。

**交付**
- “可改/不可改/条件可改”三态结论表。
- 每条结论附实验输入与输出证据。

---

### 主线 F：从“创建工程”到“激活”逐点击替换为代码

**目标**
- 把每一次 UI 点击都映射到可自动化执行的步骤。

**交付**
- 端到端步骤清单（UI 步骤、替代代码、失败回退方案）。
- 最终形成可重复执行的脚本化流程（当前入口：`Program.cs`）。

## 7) AI 协作策略（重点）

你提出的方向非常关键：不仅“让 AI 执行”，还要“让 AI 可持续地探索”。

### 7.1 AI 能高效完成的部分
- 批量生成/迭代 C# 调用代码与 XML 模板。
- 自动比对 `ProduceXml` 前后差异，归纳可写字段。
- 将实验结果结构化为表格和结论文档。

### 7.2 AI 做不到或不稳定的原因
- TwinCAT/VS COM 自动化强依赖本机 GUI 状态与权限。
- 某些动作无公开 API，且 `ConsumeXml` 语义隐式、版本敏感。
- 运行时错误常是“上下文问题”（实例繁忙、界面状态、实时态切换）。

### 7.3 建议补齐的工具能力
- **实验执行器**：给定步骤清单自动执行并打点日志。
- **XML 差异器**：自动保存 `ProduceXml` 快照并做语义 diff。
- **结论生成器**：把实验日志自动汇总为“可替代性”报告。

### 7.4 C# 脚本模式建议
- 可引入 C# 脚本化运行（如 Roslyn/C# script）来快速试错，减少“改-编译-跑”循环时间。
- 把高频实验（单个 TreeItem 的 XML 注入）做成脚本任务，AI 可更快迭代。
