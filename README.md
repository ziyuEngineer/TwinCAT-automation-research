# TwinCAT Automation Research Playbook

## 1) 项目定位

本仓库用于系统化研究 TwinCAT 3 Automation Interface（重点版本：4026）在“从工程创建到激活”全流程中的自动化可替代能力，目标是：

- 把 UI 点击步骤尽可能替换为可复现的 C# 自动化代码。
- 对“未直接暴露为属性/接口”的能力，优先探索 `ITcSmTreeItem::ConsumeXml()` / `ProduceXml()` 的可行路径。
- 对必须落到 TMC 的改动，给出可追踪、可回滚、可激活验证的标准流程。

## 8) AI 协作策略（重点）

你提出的方向非常关键：不仅“让 AI 执行”，还要“让 AI 可持续地探索”。

### 7.1 AI 能高效完成的部分
- 批量生成/迭代 C# 调用代码与 XML 模板。
- 自动比对 `ProduceXml` 前后差异，归纳可写字段。
- 将实验结果结构化为表格和结论文档。

### 7.2 AI 做不到或不稳定的原因
- TwinCAT/VS COM 自动化强依赖本机 GUI 状态与权限。
- 某些动作无公开 API，且 `ConsumeXml` 语义隐式、版本敏感。
- 运行时错误常是“上下文问题”（实例繁忙、界面状态、实时态切换）。

### 7.3 建议补齐的工具能力
- **实验执行器**：给定步骤清单自动执行并打点日志。
- **XML 差异器**：自动保存 `ProduceXml` 快照并做语义 diff。
- **结论生成器**：把实验日志自动汇总为“可替代性”报告。

### 7.4 C# 脚本模式建议
- 可引入 C# 脚本化运行（如 Roslyn/C# script）来快速试错，减少“改-编译-跑”循环时间。
- 把高频实验（单个 TreeItem 的 XML 注入）做成脚本任务，AI 可更快迭代。
